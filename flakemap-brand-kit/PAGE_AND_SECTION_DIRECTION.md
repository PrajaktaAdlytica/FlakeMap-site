## Interaction grammar

- **Trace links:** selecting a known workflow step changes a small state marker and evidence highlight. Labels remain fixed. A hover preview has focus/touch equivalents and never contains unique hidden information.
- **Primary action:** a restrained directional inset or arrow movement suggests forward progress; label remains fixed. Keep the dark navy button's focus indicator visible across all eight surfaces.
- **Module panels:** purposeful previews differ by module: Desk aligns source fields; Review emphasizes selected rows; Proof marks an injection point; Signal highlights a criterion; Report opens an evidence tab. No universal card tilt.
- **Tabs/selectors:** native buttons with explicit selected state, stable dimensions and associated panel names. Selection changes useful information; it does not merely recolor a decorative scene.
- **Review actions:** simulation state changes occur only after activation. Scrolling cannot annotate, approve, submit a form or change the source fixture silently.
- **Reset:** restores a documented initial fixture and clears only local demo annotations, with a concise confirmation when work would be discarded. Never changes real external state.
- **Export:** generated reports include concept-preview and synthetic-data labels, fixture IDs, condition, seed, versions, criterion, numerator/denominator where relevant, reviewer mock note and sample timestamp. No external transmission implied.
- **Feedback:** pending, empty, error, selected and complete states use icon + text, not color alone. Reserve warm red/error tones for failure; do not use them as ambient decoration around every CTA.

## Motion implementation contract for the eventual build

This is a plan, not a library installation request. The guide proposes GSAP ScrollTrigger for coordinated sequences; use it for the bounded homepage trace sequence if it materially helps. Native scroll remains canonical. Lenis is optional only if it improves the tested experience; do not add smooth scrolling automatically. Prefer HTML/SVG for labeled paths, tables and diagrams. Raster or video may provide optional glass material atmosphere, with a genuine editable data layer above it. WebGL is not a prerequisite for Prism Replay.

1. **Information order:** fixture/input first; selected condition next; event-order change next; resulting artifact last. Motion never visually asserts an output before the input that explains it.
2. **Stable reverse behavior:** scrubbed path transformations reverse predictably. Entrance reveals remain settled after first entry. User-selected controls persist during scrolling; scroll chapters cannot overwrite an active user simulation without an explicit “Follow story” mode.
3. **Pinning:** one narrative group at most on a sufficiently large viewport; natural entry/exit and clear chapter labels. Avoid pinning for short-height displays. Mobile story stacks into complete sections.
4. **Labels:** render required text in HTML or readable SVG with opaque support. Never bake important UI labels into a glass texture or generated background. No line crossing through labels; connectors meet ports/node boundaries.
5. **Reduced motion:** no scrubbed camera, parallax, continuous gloss or forced smooth scrolling. Show paired states, complete diagrams and final actual values. A full “Story summary” ordered list duplicates essential causal information.
6. **Input:** every control works by keyboard and touch. Meaningful hover states have focus equivalents. Timelines and matrices provide ordered tables. Do not announce every animation frame; announce completed user-requested state updates sparingly.
7. **Performance:** a compressed still can carry the hero material. Avoid rendering the entire site as a canvas, large looping background videos in every section, or heavy blur over text. Stop optional animation offscreen and in hidden tabs. Reserve asset dimensions to prevent layout shift.
8. **Honest measurement:** no metric count-up from zero; fixture values appear as final labeled values. Distinguish number of displayed examples from confidence about production reliability.
9. **No fake maps:** FlakeMap's “map” is a workflow/topology metaphor. Use stage paths, event timelines, dependency diagrams and evidence relationships. Geographic maps need genuine location questions and data; none is present here.
